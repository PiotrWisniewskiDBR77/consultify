## 📊 Analiza Aktualnego Stanu

### Obecny Problem

Po migracji z JavaScript do TypeScript pozostały **masywne duplikaty plików** - każdy serwis ma zarówno wersję `.js` jak i `.ts`. 

**Szacowane liczby (z analizy 2026-01-06):**
- `server/src/services/`: **~884 pliki `.js`** (duplikaty obok `.ts`)
- `server/src/`: setki plików `.js` obok odpowiadających im `.ts`
- GitHub pokazuje **więcej niż połowę kodu jako JavaScript** zamiast TypeScript
- Każdy serwis ma parę: `serviceName.js` + `serviceName.ts`

**Przykłady duplikatów:**
- `accessCodeService.js` + `accessCodeService.ts`
- `tokenBillingService.js` + `tokenBillingService.ts`
- `auditService.js` + `auditService.ts`
- `adminSessionService.js` + `adminSessionService.ts`
- ... i setki innych

### Metryki Aktualne
- **Duplikacja kodu:** ~50%+ kodu to duplikaty JS/TS
- **GitHub Language Stats:** Błędnie pokazuje JavaScript jako główny język (>50%)
- **Maintainability Score:** Niska - nie wiadomo który plik jest źródłem prawdy
- **Build confusion:** Możliwe że build używa starych plików `.js` zamiast `.ts`
- **Developer confusion:** Trudno określić który plik edytować
- **Code review overhead:** Czas tracony na sprawdzanie czy edytujemy właściwy plik

### Pain Points
1. **Duplikacja kodu** - **Wpływ:** Wysoki - utrzymywanie dwóch wersji tego samego kodu zwiększa koszty utrzymania o ~50%
2. **Błędne statystyki GitHub** - **Wpływ:** Średni - mylące dla nowych deweloperów i stakeholderów
3. **Ryzyko użycia starych plików** - **Wpływ:** Wysoki - możliwe że build używa `.js` zamiast `.ts`, co może prowadzić do błędów produkcyjnych
4. **Trudność w utrzymaniu** - **Wpływ:** Wysoki - nie wiadomo który plik jest źródłem prawdy, ryzyko edycji złego pliku
5. **Wydłużony czas code review** - **Wpływ:** Średni - potrzeba weryfikacji czy zmiany są w odpowiednim pliku

## 🎯 Proponowane Rozwiązanie

### Opis Usprawnienia

**Stopniowe przenoszenie plików JavaScript do kwarantanny z fazą testowania przed usunięciem.**

**Strategia kwarantanny:**
1. **Faza 1: Identyfikacja** - Znalezienie wszystkich duplikatów JS/TS i analiza które są używane
2. **Faza 2: Weryfikacja** - Sprawdzenie które pliki `.js` są faktycznie importowane w kodzie
3. **Faza 3: Kwarantanna** - Przenoszenie nieużywanych `.js` do `server/src/_quarantine/js-legacy/`
4. **Faza 4: Testowanie** - Uruchomienie pełnej baterii testów po każdej partii przeniesień
5. **Faza 5: Monitoring** - Obserwacja przez 2-3 tygodnie czy wszystko działa poprawnie
6. **Faza 6: Archiwizacja** - Po okresie stabilności przeniesienie do `server/src/_archive/js-legacy/`
7. **Faza 7: Finalne usunięcie** - Po dłuższym okresie (1 miesiąc) bezpieczne usunięcie z archiwum

**Kluczowe zasady:**
- ✅ **Stopniowość** - małe partie (10-50 plików na raz)
- ✅ **Testowanie** - pełna bateria testów po każdej partii

- ✅ **Monitoring** - obserwacja przez okres stabilności

**Krok 1.1: Utworzenie skryptu identyfikacji duplikatów**
```bash

```
- [ ] Skrypt skanuje `server/src/` rekurencyjnie

**Krok 1.2: Utworzenie skryptu analizy importów**
```bash
# Utworzyć plik: scripts/analyze-js-imports.js
```
- [ ] Skrypt analizuje wszystkie pliki w `server/src/` (`.ts`, `.tsx`, `.js`, `.jsx`)
- [ ] Szuka importów plików `.js` w następujących formatach:
  - `import ... from './service.js'`
  - `import ... from './service'` (może resolvować do `.js`)
  - `require('./service.js')`
  - `require('./service')`
  - Dynamiczne importy: `import('./service.js')`
- [ ] Tworzy mapę: które pliki `.js` są importowane i przez które pliki
- [ ] Zapisuje raport do `migration-reports/imports-analysis.json`
- [ ] Oznacza pliki jako: `USED` (używane) lub `UNUSED` (nieużywane)

**Krok 1.3: Utworzenie skryptu przenoszenia do kwarantanny**
```bash
# Utworzyć plik: scripts/move-to-quarantine.js
```
- [ ] Skrypt przyjmuje listę plików do przeniesienia (z raportu duplikatów)
- [ ] Dla każdego pliku `.js`:
  - [ ] Weryfikuje że istnieje odpowiadający `.ts`
  - [ ] Weryfikuje że plik nie jest używany (z raportu importów)
  - [ ] Tworzy strukturę katalogów w `server/src/_quarantine/js-legacy/` (zachowuje strukturę)
  - [ ] Przenosi plik zachowując ścieżkę względną (np. `services/auditService.js` → `_quarantine/js-legacy/services/auditService.js`)

- [ ] Po przeniesieniu: commit do Git z message: `chore: move JS duplicates to quarantine [PARTIA-X]`


- [ ] Dla każdego pliku w kwarantannie:
