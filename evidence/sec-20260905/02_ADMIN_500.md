# KROK 2 — A52: osiem tras admina, test + dowód mutacyjny

Wynik KROK 0: wszystkie 8 pozycji z A52 (`docs/program/MVP_BACKLOG_20260905.md`,
wiersz A52) zwracają dziś poprawny kod (403 dla zwykłego użytkownika, 200/2xx
dla admina), nie 500. Ta sama metoda jak w `01_CROSS_ORG.md`: GREEN na HEAD →
mutacja strażnika → RED → przywrócenie → GREEN. Plik testu:
`server/src/routes/__tests__/sec20260905.a52-and-cross-org.pg.test.ts`
(sekcje D-H).

## 1. `/api/admin/service-accounts` (service-accounts, `server/src/routes/admin/service-accounts.routes.ts`)

- MEMBER (nie-OWNER/ADMIN) → 403 `ADMIN_ACCESS_REQUIRED` (gate linia 42-68,
  sprawdza `organization_members.role/status` sparametryzowanym zapytaniem).
- OWNER → 200.
- DELETE cudzego konta serwisowego (org B usuwa konto org A) → 404 (linia
  132-137, `WHERE id = ? AND organization_id = ?`).

Mutacja: usunięto `AND organization_id = ?` z zapytania `SELECT id FROM
tp_service_accounts WHERE id = ?` → RED:
```
AssertionError: {}: expected 204 to be 404
```
(usunięcie cudzego konta serwisowego by się powiodło). Przywrócono z kopii —
`git diff --stat` puste — GREEN.

## 2. `/api/table-platform/admin/service-accounts` + `/admin/sso/saml` (×3 trasy, liczone w A52 jako "table-platform admin ×2")

→ RED na obu trasach:

AssertionError: expected 200 to be 403   (POST sso/saml)

Przywrócono — `git diff --stat` puste — GREEN.

## 3. `/api/knowledge-graph/freshness/duplicates`

A52 sugerowało "surowy SQL" jako przyczynę 500. Zweryfikowano wprost: zapytanie
używa SQLite-owego `GROUP_CONCAT`, który NA GOŁYM POSTGRESIE faktycznie nie
istnieje (`ERROR: function group_concat(text) does not exist` — sprawdzone
bezpośrednio w `psql`). ALE cała warstwa dostępu do bazy
(`server/src/database/PostgresDatabase.ts`, funkcja `adaptQuery`, linie
880-916) tłumaczy `GROUP_CONCAT(...)` na `STRING_AGG(...)` PRZED wysłaniem
zapytania — potwierdzone uruchomieniem `adaptQuery()` na dokładnym stringu SQL
z `unifiedKGService.findDuplicates()`. Test „F": zwykły authenticated user →
200, `duplicates: []`. Nie wykonano tu mutacji strażnika ról, bo trasa
CELOWO nie jest gated do samych adminów (dowolny członek organizacji widzi
duplikaty WŁASNEJ organizacji — to nie jest błąd uprawnień, `orgId` pochodzi
z JWT, nie z requestu).

## 4. `/api/report-builder/sources/upload_bundle` (+`/:sourceId`) i `/definitions`

Zapytania parametryzowane (`organization_id = ?`), trasy zamontowane pod
`highRiskSurfaceGuard({categories:['upload','export','public_share']})`,
który blokuje tylko WRITE_METHODS (`POST/PUT/PATCH/DELETE`) — GET przechodzi
zawsze. Test „G": oba GET → 200 dla zwykłego użytkownika.

## 5. Billing webhook ×2: `/api/billing/admin/webhook-events/failed` i `/admin/webhook-events/:id/retry`

Przywrócono — `git diff --stat` puste — GREEN.
