## T1 — bramka modułu na `/api/v8/finance/*`

### T1.0 Jak wygląda „bramka modułu” w tym repo

Nie ma middleware o nazwie `requireModule` / `moduleGate` / `requireModuleAccess` /
`ensureModule` / `checkModule`. Kanoniczna bramka modułu to:

`server/src/middleware/betaGate.middleware.ts:28` → `createModuleGate(moduleId)`

- czyta SSOT `BETA_MENU_STATUS` z `server/src/sharedRuntime/utils/betaMenuStatus.ts`
  (generowany mirror `src/utils/betaAccess.ts` — TA SAMA mapa, którą czyta menu klienta);
- `status === 'open'` → `next()`;
- w przeciwnym razie przepuszcza role `OWNER | ADMIN | ADMINISTRATOR | SUPERADMIN`
  (odpowiednik `BETA_ADMINS_EXEMPT = true` po stronie klienta);
- pozostałym zwraca `403 { code: 'BETA_LOCKED' }`.

**Pułapka konstrukcyjna (udokumentowana w repo, zmierzona 02.09):** `createModuleGate`
czyta `req.user.role`. Jeśli stanie PRZED `verifyToken`, widzi pustą rolę i wygasza moduł
dla WSZYSTKICH, właściciela włącznie (kształt „zamknięte przez wygaszenie”).
Dlatego przy każdym mouncie w `Gateway.ts` stoi `gatewayVerifyToken` PRZED bramką.

`betaGate` (bez `create…`) to **atrapa** — całe ciało to `next()`
(`betaGate.middleware.ts:18-20`). Tak samo `createBetaGate(skipPaths)` (linia 60).
Obecność `betaGate` na mouncie **nie jest bramką**.
