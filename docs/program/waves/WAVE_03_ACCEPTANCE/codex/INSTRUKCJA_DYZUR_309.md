## R3 — DOWÓD MUTACYJNY (rdzeń)

Co najmniej dwadzieścia bloków oznaczonych jako puste: skasuj ciało funkcji produkcyjnej, pokaż,
że test nadal przechodzi, przywróć. Bez tego klasyfikacja jest opinią, a opinia o testach jest
dokładnie tym, co ten dyżur ma zastąpić.

Commit po `R3`.

## R4 — WZMOCNIENIE (rdzeń)

Asercja mocniejsza albo `test.todo` z powodem i numerem pozycji. **Nie kasujesz testów** —
skasowany test znika także z rejestru długu. Jeżeli wzmocnienie odsłoni realny defekt produktu,
naprawiasz go osobnym commitem z własnym dowodem.

Commit per grupa.

## R5 — BEZPIECZNIK (rdzeń)

Test czerwieniący się przy nowym bloku o asercjach wyłącznie słabych, z linią bazową równą
stanowi po naprawie, z własnym dowodem mutacyjnym. Przy okazji sprawdzasz, czy pięć twierdzeń
bezpieczeństwa opisanych w rejestrze decyzji nadal jest czerwonych przy wyłączonym ponawianiu.

Commit po `R5`.
