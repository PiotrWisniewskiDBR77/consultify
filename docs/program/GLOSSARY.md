# Słownik Consultinity

| Pojęcie | Definicja |
| --- | --- |
| Artefakt | Trwały wynik pracy: dokument, tabela, prezentacja, raport, mapa lub inny obiekt, który można otworzyć, wersjonować i powiązać ze źródłami. |
| Assessment | Ustrukturyzowana ocena według modelu/metodyki, prowadząca do scoringu, luk, raportu i kandydatów inicjatyw. |
| Audyt | Kontrolowany program porównania stanu z wymaganiem lub standardem, oparty na dowodach i ustaleniach. |
| Audit Blueprint | Zatwierdzony i wersjonowany przepis na audyt utworzony z normy, instrukcji lub ręcznie: wymagania, pytania, dowody, testy, role i reguły raportowania. |
| Decyzja | Jawny wybór posiadający autora, kontekst, status i konsekwencje. |
| Evidence | Datowany dowód dotyczący konkretnego stanu, testu, zachowania lub odbioru. |
| GAP | Różnica między potwierdzonym AS-IS a zaakceptowanym TO-BE. |
| Generation Brief | Zatwierdzany przed produkcją plan materiału: cel, odbiorca, struktura, źródła, plan wizualny, a dla workbooka także założenia, wejścia, logika i wyniki. |
| Handoff | Jawne przekazanie pracy lub obiektu między modułami albo właścicielami. |
| Initiative | Główny obiekt planowanej zmiany: łączy problem, cel, zakres, właściciela, wartość, plan i governance. |
| Initiative Candidate Pack | Kontrolowana propozycja inicjatywy z problemem/szansą, uzasadnieniem, źródłami, oczekiwanym wpływem, KPI, ryzykami i brakami; przed review nie jest zatwierdzoną inicjatywą. |
| Investment Case | Wersjonowana analiza opłacalności inwestycji obejmująca założenia, koszty, korzyści, przepływy, scenariusze oraz NPV/IRR/ROI/payback; może działać bez pełnego modelu przedsiębiorstwa. |
| Benefits Realization Ledger | Rejestr porównujący zatwierdzoną obietnicę inwestycyjną z rzeczywistymi kosztami, KPI, korzyściami i ponownie obliczoną opłacalnością. |
| Confirmed Benefit | Korzyść potwierdzona na podstawie zdefiniowanego KPI, okresu, źródła, pomiaru i review; samo ukończenie pracy ani deklaracja właściciela nie wystarcza. |
| Deviation Case | Zarządzany przypadek odchylenia prowadzący od wykrycia i RCA przez decyzję oraz działanie do weryfikacji skuteczności i zamknięcia. |
| KPI Recovery Card | Karta zarządzania powrotem KPI do oczekiwanych parametrów, obejmująca odchylenie, RCA, działania, właścicieli, terminy, checkpointy i ocenę skuteczności. |
| KPI Registry | Kanoniczna tabela wszystkich KPI dostępnych w danym zakresie uprawnień, niezależna od kart, na których są prezentowane. |
| Key Result | Mierzalny, ograniczony czasowo rezultat pokazujący postęp względem Objective; nie jest listą zadań ani samą Initiative. |
| Objective | Krótki, jakościowy i angażujący opis tego, co organizacja lub zespół chce osiągnąć w określonym cyklu OKR. |
| OKR Definition Brief | Podsumowanie celu, Key Results, baseline, targetów, źródeł, ownerów, rytmu, ryzyk i widoczności przedstawiane przed aktywacją OKR. |
| Results Snapshot | Niezmienny, wersjonowany stan KPI, pomiarów, odchyleń i narracji użyty podczas review albo publikacji raportu. |
| Scorecard | Wersjonowany zestaw odwołań do KPI dla określonego celu, zakresu i odbiorcy; nie kopiuje definicji ani pomiarów KPI. |
| Insight | Wniosek oparty na źródle, np. odpowiedziach z Interview; nie jest automatycznie decyzją ani inicjatywą. |
| Materials | Moduł tworzenia i przechowywania dokumentów, arkuszy, prezentacji i raportów. |
| Meeting | Wieloosobowe środowisko pracy orkiestrujące przygotowanie, aktywną facylitację Teresy, wspólne narzędzia, domknięcie i publikację rezultatów do modułów właścicielskich. |
| Meeting Contract | Wersjonowane zasady pojedynczego spotkania: cel, role, kontekst, poziom autonomii Teresy, dostępne narzędzia, zgody i sposób publikacji. |
| Meeting Orchestrator | Warstwa pozwalająca Teresie bezpiecznie czytać kontekst całej aplikacji, uruchamiać narzędzia i przekazywać zatwierdzone rezultaty bez kopiowania źródeł prawdy. |
| My Work | Osobista powierzchnia skupiająca pracę użytkownika i dostęp do jego obiektów roboczych. |
| Partner | Firma, konsultant lub inny podmiot uczestniczący w Programie Partnerskim, który może sprzedawać, a w rozszerzonym wariancie także wdrażać Consultinity. |
| Partner polecający | Osoba fizyczna uczestnicząca w Programie Poleceń, posiadająca własny kod i prawo do wynagrodzenia za skuteczne polecenie. |
| Portal Partnera | Wspólna chroniona powierzchnia techniczna obsługująca oddzielne ścieżki Programu Poleceń i Programu Partnerskiego. |
| Program Poleceń | Prosta formuła dla osób fizycznych: poznaj aktualny produkt, zaakceptuj zasady, otrzymaj kod, polecaj i rozliczaj skuteczne sprzedaże. |
| Program Partnerski | Rozszerzona formuła dla firm, konsultantów i wdrożeniowców obejmująca sprzedaż, certyfikację oraz opcjonalne usługi i dostęp delivery. |
| Provenance | Informacja skąd pochodzi dana, twierdzenie lub element artefaktu i jak został przetworzony. |
| Runtime | Rzeczywiste działanie kodu na określonym środowisku. |
| Session Ledger | Chronologiczny rejestr źródeł, interwencji, narzędzi, wersji roboczych, akceptacji i publikacji powstałych podczas sesji. |
| Sesja | Konkretne uruchomienie Interview, Tool, Assessment, agenta lub innego procesu. |
| Source link | Trwałe powiązanie obiektu wynikowego z obiektem źródłowym. |
| Teresa | Główna persona/interfejs AI Consultinity wspierająca rozmowę, analizę i działania. |
| Tool | Metodyka lub narzędzie konsultingowe uruchamiane jako śledzalna sesja. |
| AS-IS | Potwierdzony stan obecny. |
| TO-BE | Zaakceptowany stan docelowy. |
| NEXT | Uzgodniona kolejność najbliższych prac domykających GAP. |

## Reguła językowa

Jeśli nazwa biznesowa różni się od technicznej, dokumentacja używa nazwy
widocznej dla użytkownika, a nazwę kodową podaje w backtickach.
