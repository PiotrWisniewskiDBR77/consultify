## Delivered

E1 adds a feature-gated AI analysis path to the existing Plan analysis command. The service sends the exact versioned plan horizon and tenant-scoped initiative snapshot to the configured premium LLM, validates the returned dependency graph, separates absolute and conditional paths, and rejects ungrounded or cyclic output. A successful result is stored in the existing versioned `plan_analysis_proposal` aggregate with its model, analysis timestamp, scenario version, observations, and critical paths.

The runtime reads source fields and existing edges from PostgreSQL. It refuses incomplete plan context. Provider failure returns `AI_UNAVAILABLE`; invalid model output returns `AI_RESPONSE_INVALID`. There is no fallback that presents generated or solver data as AI analysis.

`VITE_INITIATIVES_PLAN` and `ENABLE_INITIATIVES_PLAN` remain fail-closed unless each value is exactly `true`. The request schema defaults to the existing `SOLVER` path, so the OFF line retains the established Plan workspace and behavior.

The independent E1 reviews found two command-ordering defects. Both are repaired in the current freeze: the route compares the normalized URL scenario ID with the body before lookup, while the domain checks the stored receipt before validating the current source Plan version. The external analysis remains deferred until both receipt and version handling are complete. Replaying the same proposal and `clientRequestId` after the source Plan advances returns the stored response without another LLM call; a fresh request against the stale version returns 409 without calling AI.
