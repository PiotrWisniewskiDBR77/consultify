## Niezweryfikowane

1. **`Api.createProject` / `POST /api/chat-projects`** (MoveToProjectModal → "Utwórz folder", poz. #26) — nie odczytano pełnej implementacji `createProject` w `useChatProjectStore.ts` ani nie wykonano osobnego `curl` na `POST /api/chat-projects` (bez segmentu `/conversations/...`). Wysoka pewność że działa (ten sam plik routera co zweryfikowany `move`), ale brak bezpośredniego dowodu — klasyfikacja NIEPEWNY.
2. **`@`-mention źródła** (poz. #54) — `useMentionSources` może odpytywać bazę wiedzy/dokumenty w tle (KB search wspomniany w komentarzu `EnhancedChatInput.tsx:255-257`), ale nie prześledzono czy to faktyczne wywołanie HTTP czy tylko filtr po już wczytanych danych w store. Sklasyfikowano ostrożnie jako OK-LOKALNY, wymaga dodatkowej weryfikacji jeśli ma znaczenie produktowe.
3. **Org internet policy dla "Dodaj link"** — kod jasno pokazuje gate `AIPolicyEngine.internetEnabled` (403 gdy OFF), ale nie zweryfikowano na żywym stanowisku jaka jest domyślna wartość tej polityki dla organizacji demo/staging (brak bezpiecznego sposobu sprawdzenia bez logowania).
4. **`POST /api/cloud/sources` — czy backend gdzieś indziej (np. inny endpoint OAuth callback poza zakresem tego audytu) faktycznie wymienia authorization code na token** — przeszukano `server/src/services/integrationOAuthEngine.ts` pobieżnie (potwierdzone wpisy dla onedrive/dropbox z realnymi `authorizeUrl`/`tokenUrl`), ale nie ustalono, czy JAKIKOLWIEK ekran w aplikacji faktycznie uruchamia ten silnik dla kontekstu "Cloud Data Sources" czatu (silnik może obsługiwać inny, niepowiązany typ integracji — np. Slack). To wzmacnia, a nie osłabia, klasyfikację D-1 jako atrapy dla ŚCIEŻKI Z CZATU, ale nie przesądza czy `integrationOAuthEngine.ts` jest w ogóle osiągalny z tego ekranu.
