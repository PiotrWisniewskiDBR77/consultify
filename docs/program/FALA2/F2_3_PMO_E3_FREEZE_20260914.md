# F2-3 PMO E3 — freeze candidate

**Werdykt:** kandydat E1 realizuje tworzalne projekty, role i alokacje oraz pięć bramek PMBOK-lite; pozostaje za domyślnie wyłączoną flagą `VITE_PMO_PROJECTS` i czeka na niezależny przegląd.

## Zakres zachowania

- `/projects` zachowuje przekierowanie do `/my-work` przy fladze OFF i montuje kanoniczny ekran projektów przy ON.
- Użytkownik tworzy projekt w UI, otwiera go w `StandardPreview`, przypisuje kanoniczne role DEC-488 i ustawia alokację per osoba zgodnie z DEC-480.
- Widok pokazuje odpowiedzialności, plan komunikacji i wejścia do akceptacji wyprowadzone z ról projektu.
- `StandardTable` pokazuje pięć przejść PMBOK-lite: Context → Assessment → Initiatives → Roadmap → Execution → Stabilization.
- Kryteria są liczone z istniejących danych. Brak danych lub błąd zapytania zamyka bramkę; nie ma atrap `true`.
- Zatwierdzenie wymaga roli projektu Sponsor, Leader, Steering Committee albo PMO. Uprawnienie aplikacyjne z wildcardem nie omija roli projektowej.
- Odczyt obcego projektu kończy się 404 przed oceną uprawnienia. Zapis bramki i zmiana fazy są atomowe na jednym połączeniu PostgreSQL.
- Nie powstała druga implementacja H1b ani nowy rejestr propozycji przejść. Późniejsze filtry projektów Inicjatyw i Realizacji mogą użyć istniejącego `project_id` po wejściu ich zakresu.

## Migracja 20262190

`server/migrations/20262190_f2_3_pmo_stage_gates.sql` jest pojedynczą zmianą addytywną: `CREATE TABLE IF NOT EXISTS stage_gates`, pięć wartości `gate_type`, FK `projects(id) ON DELETE CASCADE` i dwa indeksy. Nie zawiera danych, backfillu, `DROP` ani `ALTER`; nie koliduje z pulą F2-E od 20262200.

Dowód migracyjny:

- strict empty PostgreSQL: dwa przejścia;
- kopia schematu linii: dwa przejścia i idempotencja;
- źródło schematu miało faktycznie 1809 tabel publicznych, po migracji 1810; liczba 1818 ze zlecenia nie była reprodukowalna lokalnie;
- rollback operatorski: `DROP TABLE IF EXISTS stage_gates;`;
- release gate i pliki Railway bez zmian.

## Znane granice

- Flaga chroni powierzchnię UI; istniejąca rodzina backendowa `/api/stage-gates` pozostaje wspólna dla wcześniejszych wywołań.
