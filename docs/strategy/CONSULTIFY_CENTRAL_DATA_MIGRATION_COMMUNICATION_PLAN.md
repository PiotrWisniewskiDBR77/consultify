# Consultify Central Data Migration
## Communication and Adoption Plan

Version: draft v1  
Owner: Product + GTM + Engineering  
Scope: migration from fragmented tooling to Consultify as central data and analysis hub

## 1. Purpose

This document defines the communication and adoption plan for positioning Consultify as the central point for collecting, structuring, analyzing, and operationalizing business data.

The immediate migration challenge is predictable:

- users already work in Airtable
- analytics teams already work in Power BI
- operational teams already work in external PM, storage, and source systems

If Consultify wants these users to transition calmly, the product cannot be presented as "replace everything on day one."

It must be presented as:

- a central control point
- a governed data and artifact layer
- a low-risk migration path
- a system that coexists before it replaces

## 2. Strategic message

The core migration story should be:

`Keep your current sources. Move your control, modeling, analysis, and decision flow into Consultify.`

This message matters because Airtable and Power BI already own part of the user mental model:

- Airtable owns flexible operational data modeling
- Power BI owns dashboards and semantic analytics

Consultify should not initially fight that mental model.

It should unify it.

## 3. Positioning against Airtable and Power BI

### 3.1 Airtable migration message

For Airtable users, the message should be:

- bring your operational data into Consultify
- keep familiar table workflows
- gain better governance, links to initiatives, AI, reports, decisions, and downstream actions

### 3.2 Power BI migration message

For Power BI users, the message should be:

- keep source systems and analytics discipline
- move KPI ownership, context, decisions, ROI, and action loops into Consultify
- use Consultify as the governed operational layer around analytics, not only the dashboard viewer

## 4. What we are not promising

To avoid adoption backlash, communication must explicitly avoid promising:

- full Airtable parity on day one
- full Power BI parity on day one
- instant migration of every connector and dashboard
- all-in-one automation in the first rollout

Instead, the promise should be:

- practical migration
- strong centralization of trusted data
- reusable operational views
- better downstream execution and reporting

## 5. Adoption principle

Migration should follow:

`coexist -> mirror -> validate -> switch primary workflow -> retire old dependency where justified`

This is safer than a big-bang replacement story.

## 6. Audience map

The communication plan must address different audiences separately.

### 6.1 Executives and sponsors

They care about:

- governance
- one source of trusted decisions
- auditability
- reporting consistency
- lower fragmentation

Message:

Consultify becomes the operating system around data, analysis, decisions, and business artifacts.

### 6.2 Operators and team leads

They care about:

- simple tables
- fewer duplicate updates
- reliable imports
- clear ownership
- less manual reporting

Message:

Consultify reduces copy-paste work and lets teams operate on live, connected data.

### 6.3 Analysts and finance users

They care about:

- trustworthy data models
- refresh behavior
- traceability
- KPI and finance provenance
- stable exports

Message:

Consultify adds governed operational modeling and actionability on top of analytics workflows.

### 6.4 Admins and IT

They care about:

- access control
- rollout risk
- connector governance
- audit
- reversible migration

Message:

Consultify supports controlled enablement, source coexistence, and policy-based rollout.

## 7. Migration promise by phase

### Phase 1: Connect and mirror

Promise:

- no forced replacement
- connect existing sources
- import or sync selected data into Consultify
- validate models and views

Primary communication:

- "Start by bringing selected data into Consultify."
- "Do not rebuild everything manually."

### Phase 2: Run dual workflow for priority cases

Promise:

- selected teams can run operational workflows in Consultify
- data remains reconcilable against source systems
- dashboards and reports gain business context and governance

Primary communication:

- "Use Consultify as the operating layer while keeping source confidence."

### Phase 3: Make Consultify the working center

Promise:

- Consultify becomes the daily point of entry for data-backed work
- selected legacy workflows can be retired where ROI is proven

Primary communication:

- "Your source systems still matter, but Consultify is now the place where work, analysis, and decisions converge."

## 8. Communication pillars

The communication plan should be built around five repeated pillars.

### Pillar 1: No forced rip-and-replace

Users must hear clearly that Consultify supports coexistence and staged migration.

### Pillar 2: Central visibility

Consultify gives one place for:

- tables
- KPIs
- finance context
- reports
- decisions
- initiative execution

### Pillar 3: Governed data, not just dashboards

This is the main differentiator against fragmented Airtable plus Power BI usage.

### Pillar 4: Trusted lineage

Users need confidence that imported, synced, or manually edited data is visible, attributable, and auditable.

### Pillar 5: Better downstream action

Data in Consultify should not end as passive reporting.

It should connect to:

- initiatives
- tasks
- risks
- decisions
- reports and presentations

## 9. Core objections and how to answer them

### Objection 1

"We already have Airtable."

Answer:

Airtable is good for flexible table workflows. Consultify is intended to connect that operational data with initiatives, ROI, governance, reports, and execution in one system.

### Objection 2

"We already have Power BI."

Answer:

Power BI is strong for dashboards and semantic analytics. Consultify is the layer that turns data into governed business workflows, action loops, and reusable artifacts.

### Objection 3

"Migration will be painful."

Answer:

The recommended path is staged and source-preserving. Start with selected synced tables and governed KPI flows, not a whole-company cutover.

### Objection 4

"We do not want another isolated tool."

Answer:

Consultify should be deployed as a central coordination layer with connectors, lineage, and artifact outputs, not as another disconnected workspace.

## 10. Minimum communication assets

Before rollout, the product should have:

- one migration narrative deck
- one Airtable migration one-pager
- one Power BI migration one-pager
- one admin runbook for source connection
- one pilot FAQ
- one objection-handling script for sales and onboarding

## 11. Recommended rollout communication sequence

### Step 1

Introduce Consultify as the central data and analysis operating layer.

### Step 2

Show coexistence:

- import from files
- sync from source systems
- preserve source references

### Step 3

Show practical wins:

- one governed table
- one KPI flow
- one executive pack
- one action loop from deviation to task

### Step 4

Expand to broader migration only after one pilot proves value.

## 12. Product guardrails for communication

Do not communicate features as complete if the product does not yet provide:

- connector governance
- refresh visibility
- provenance
- stable table contracts
- audit-ready exports

The adoption plan fails if messaging outruns product reality.

## 13. Success metrics

The communication strategy is working if:

- pilot users connect real data sources without high migration anxiety
- teams can identify Consultify as the daily operational hub
- users understand that source systems can coexist initially
- stakeholders stop treating Consultify as "just another dashboard tool"
- adoption expands from one workflow to multiple linked workflows

## 14. Final recommendation

The migration story should not be:

`Leave Airtable. Leave Power BI. Start over in Consultify.`

It should be:

`Bring your existing data ecosystem into Consultify, validate it there, and progressively make Consultify the central place where analysis, decisions, and operational follow-through happen.`
