# Wave 2 Module Card — Agenci / KIMI / Prompty / Palantir

> Cluster: `Entry And AI OS Expansion`
> Scope: broad AI operating-system product family beyond bounded chat and prompt infrastructure

## 1. Module scope

This card covers the broad AI OS family:

- user-facing agent experience,
- KIMI-style operating model,
- prompt operating system as visible platform capability,
- governed multi-agent work,
- and Palantir-like knowledge truth as a benchmark direction rather than a direct module clone.

## 3. Intended product behavior

This family should make Consultify feel like a real AI operating environment:

- chat starts governed work,
- prompts are managed as platform assets,
- agents can plan, propose, and coordinate work,
- knowledge is policy-aware and traceable,
- and the user experiences one coherent AI system rather than scattered AI features.

## 4. Current repo and doc truth

Current truth is strong in architecture and weak in product packaging:

- `Prompt OS`, `Agent`, and `Knowledge` docs are strong,
- `SYSTEMATYKA` calls AI planning coverage one of the strongest layers,
- but the gap analysis still classifies `Prompty / KIMI / Agenci` as only partially delivered and pushed to `8.2`,
- so the platform doctrine exists while the broad user-facing suite remains unfinished.

## 5. Competitive standard

Wave 2 should judge this against:

- KIMI-style artifact-native behavior,
- ChatGPT / Claude / Perplexity-grade chat expectations,
- strong multi-agent work managers,
- and ontology/lineage-first enterprise systems as inspiration for governed knowledge truth.

## 6. Current-state assessment

- `User value`: partial. Underlying capability is rich, visible suite-level product is still incomplete.
- `Flow completeness`: partial. Chat, prompt, execution, and knowledge flows exist, but not yet as one user-facing OS.
- `UX quality`: partial. Product packaging still lags behind doctrine.
- `Data / logic quality`: strong. Execution and retrieval architecture is serious.
- `Integration quality`: strong. The documents already define one shared AI spine.
- `Trust / governance`: strong. Governance is one of the best-developed layers.
- `Market standard fit`: partial. Strong foundations, incomplete visible convergence.

## 7. Main gaps

- no one user-facing AI operating system surface,
- no unified agent product identity,
- prompt OS is still more platform-governance than end-user capability,
- knowledge truth and lineage are not yet packaged as a visible advantage,
- KIMI-like behavior is defined in artifacts, not fully generalized across the AI OS family.

## 8. Minimal acceptance state now

The first acceptable Wave 2 state is:

- one explicit AI OS product map,
- one governed prompt-release and prompt-mutation path,
- one visible agent work model,
- and one policy-aware knowledge path tied to execution and outputs.

## 9. Full 100% target state

This family reaches 100% only when Consultify provides:

- one coherent AI operating environment,
- user-visible prompt controls where appropriate,
- multi-agent orchestration,
- policy-aware knowledge and working memory,
- artifact-native generation and continuation,
- and explicit traceability, approval, and audit across the whole stack.

## 10. Top missing functions and flows

- one AI OS surface map for users and operators
- prompt release and prompt teaching lifecycle visible beyond admin-only framing
- multi-agent task handoff and coordination
- governed knowledge truth and lineage visible to the user
- unified AI run lifecycle from ask to plan to approve to apply to audit

## 11. Proposed bounded delivery packets

1. `AI OS product map`
   - turn strong architecture docs into one visible product family
2. `Prompt OS convergence`
   - close mutation, release, observability, and traceability into one real lifecycle
3. `Agent work manager`
   - make agent orchestration and task handoff visible and governed
4. `Governed knowledge truth`
   - package lineage, policy-aware retrieval, and working memory as one user-trust story

## 12. Risks and dependencies

- depends on `Chat`, `Knowledge RAG`, `Prompt OS`, `Execution Agent`, and `Outputs`,
- risks collapsing many separate doctrines into one vague AI umbrella,
- risks overpromising “agent product” before user-facing flows are actually coherent.
