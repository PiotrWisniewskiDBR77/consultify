# Wave 2 Module Card — Assessment

> Cluster: `Business Enablement`
> Scope: unified assessment runtime beyond isolated packs and bounded bridge behavior

## 1. Module scope

This card covers:

- the shared assessment workbench,
- DRD / SIRI / ADMA and adjacent assessment families,
- scoring, review, AI guidance,
- and promotion of assessments into downstream work.

## 3. Intended product behavior

`Assessment` should operate as one governed assessment family:

- choose or start a methodology,
- collect answers and evidence,
- score and interpret results,
- use AI carefully,
- and promote findings into tools, initiatives, reports, or outputs.

## 4. Current repo and doc truth

Current truth is partial:

- there are real V3 assessment packs,
- there is assessment integration inside the tools bridge,
- but `SYSTEMATYKA` still marks assessment as lacking one unified V8 architecture,
- so the module is documented as important, but not yet closed as one full modern package.

## 5. Competitive standard

The benchmark is not just form completion.
It is structured diagnostic work where:

- methodology is clear,
- evidence and scoring are trustworthy,
- AI assists but does not hallucinate authority,
- and results convert into action.

## 6. Current-state assessment

- `User value`: partial. Strong methodology content exists, weak unified product framing.
- `Flow completeness`: partial. Packs exist, one common runtime still needs better closure.
- `UX quality`: partial. Shared workbench expectations exist, but the broad package is not unified.
- `Data / logic quality`: good. Method packs and scoring logic are serious.
- `Integration quality`: good. Assessment already connects into tools and downstream outputs.
- `Trust / governance`: good. The bridge obligations imply strong governance.
- `Market standard fit`: partial. The module is more method-rich than product-finished.

## 7. Main gaps

- no single `Assessment v8` package,
- no broad execution-grade assessment system plan,
- methodology packs are stronger than shared runtime packaging,
- AI support exists conceptually, but not as one clearly productized system.

## 8. Minimal acceptance state now

The first acceptable Wave 2 state is:

- one unified assessment module definition,
- one shared workbench logic,
- and one explicit path from assessment completion to downstream action or output.

## 9. Full 100% target state

`Assessment` reaches 100% only when it provides:

- one shared workbench,
- first-class methodologies,
- evidence and scoring discipline,
- AI-guided support with visible governance,
- compare/review/export flows,
- and clean promotion into tools, initiatives, reports, and outputs.

## 10. Top missing functions and flows

- shared assessment entry and method selection
- answer/evidence/scoring loop
- AI-assisted interpretation with governance
- compare/review/finalization flow
- promotion to downstream governed work

## 11. Proposed bounded delivery packets

1. `Assessment v8 canon`
   - unify pack truth and shared runtime doctrine
2. `Shared workbench closure`
   - define one workbench model for all assessment families
3. `AI-guided scoring and interpretation`
   - make AI assistance visible, bounded, and governed
4. `Assessment promotion closure`
   - close promotion to tools, initiatives, reports, and outputs

## 12. Risks and dependencies

- depends on `Tools`, `Outputs`, and `Knowledge`,
- risks remaining a collection of packs without one runtime,
- risks overfitting to one methodology instead of shared assessment grammar.
