# Wave 2 Module Card — Landing

> Cluster: `Entry And AI OS Expansion`
> Scope: broad public landing beyond bounded `Anna`

## 1. Module scope

This card covers the broad `Landing` program:

- public IA,
- value narrative,
- demo/trial convergence,
- conversion architecture,
- expert/value proof layers,
- and commercial shell coherence.

It does not cover the bounded `Anna` assistant contract as a standalone module.

## 3. Intended product behavior

`Landing` should work as a real public growth system:

- explain the category quickly,
- prove value credibly,
- route users into demo or trial,
- introduce `Anna` as a guide, not a detached widget,
- and keep every commercial narrative surface aligned.

## 4. Current repo and doc truth

Current truth is mixed:

- `Anna` has a strong bounded contract and many closed packets,
- `LANDING_V8_SSOT.md` defines a minimal viable landing canon,
- but documentation coverage still says broad landing remains weaker than stronger product areas,
- and visual/content breadth is intentionally left outside the minimal landing SSOT.

## 5. Competitive standard

Wave 2 should judge landing against:

- strong AI-first public entry points,
- modern SaaS conversion funnels,
- and category-creating product sites where narrative, proof, and CTA are one system.

The benchmark is not visual mimicry.
The benchmark is clarity, trust, conversion flow, and believable positioning.

## 6. Current-state assessment

- `User value`: partial. The category and value are defined, but not yet fully translated into one high-conviction public shell.
- `Flow completeness`: partial. Demo/trial flow exists conceptually, but the full commercial sequence is still thin.
- `UX quality`: partial. Minimal IA exists; broader page-system quality is still under-specified.
- `Data / logic quality`: good. Demo/trial convergence logic is better defined than the public shell itself.
- `Integration quality`: partial. `Anna`, demo, trial, and public messaging are connected, but not yet one polished system.
- `Trust / governance`: good. Messaging anchors and boundaries are documented.
- `Market standard fit`: partial. Stronger than an empty marketing page, below a mature public product shell.

## 7. Main gaps

- no full `Landing` package for hero, sections, proof, expert layer, and conversion system,
- no final visual/content plan for assets and proof blocks,
- no explicit expert showcase/runtime layer,
- limited commercial narrative depth outside the minimal SSOT,
- bounded `Anna` work is stronger than the rest of the landing shell.

## 8. Minimal acceptance state now

The first acceptable Wave 2 state is:

- one canonical landing IA implemented and internally consistent,
- one coherent CTA funnel from hero to demo/trial,
- `Anna` embedded as a guided entry inside that narrative,
- demo/trial copy aligned to V8 language,
- and no major public page uses old positioning language.

## 9. Full 100% target state

`Landing` reaches 100% only when it includes:

- complete public IA,
- final messaging hierarchy,
- strong visual/content system,
- expert and trust layers,
- strategic proof moments tied to real product areas,
- full demo/trial/onboarding convergence,
- multilingual public continuity,
- and one measurable conversion architecture.

## 10. Top missing functions and flows

- `Hero -> proof -> CTA` funnel with no dead sections
- expert showcase and use-case mapping
- demo-value path that highlights product depth, not only access
- trial onboarding continuity from public promise to in-app first value
- commercial copy governance across landing, demo, trial, and follow-up surfaces

## 11. Proposed bounded delivery packets

1. `Landing narrative closure`
   - align hero, problem, platform pattern, value layers, and CTA hierarchy
2. `Landing proof system`
   - add trust, experts, use cases, and proof blocks
3. `Demo/trial convergence`
   - align every commercial surface to one V8 narrative
4. `Public visual/content system`
   - define the reusable asset/content model without reopening the whole app shell

## 12. Risks and dependencies

- depends on `BUSINESS_POSITIONING_SSOT.md` staying canonical,
- depends on bounded `Anna` work not being rewritten by accident,
- risks drifting into broad marketing redesign without packet boundaries,
- depends on demo/trial product truth and onboarding continuity.
