# Wave 2 Module Card — Pelny Reports / Presentations builder

> Cluster: `Outputs And Artifact Family`
> Scope: full office-style authoring and composition layer beyond the artifact substrate and library

## 1. Module scope

This card covers:

- rich authoring,
- structured editing,
- builder continuity,
- composition and layout depth,
- and the office-style product ambition behind reports and presentations.

## 3. Intended product behavior

This module should deliver a true builder experience:

- compose and edit substantial report and deck artifacts,
- continue drafts meaningfully,
- manage structure and quality,
- and support office-grade work rather than only generated first drafts.

## 4. Current repo and doc truth

Current truth is intentionally split:

- docs for reports and presentations are broad and serious,
- the artifact-runtime closure is green for the substrate and bounded family behavior,
- but the gap analysis still explicitly says the full office-style builder remains a broader `8.2` topic.

## 5. Competitive standard

The benchmark is:

- Gamma for AI-first generation,
- Beautiful.ai for quality discipline,
- Pitch for collaboration and delivery,
- and office-style editing systems for durable authoring.

## 6. Current-state assessment

- `User value`: partial to good.
- `Flow completeness`: partial.
- `UX quality`: partial. Strong generators, not yet full office-grade builder depth.
- `Data / logic quality`: good.
- `Integration quality`: good.
- `Trust / governance`: good.
- `Market standard fit`: partial.

## 7. Main gaps

- rich editing and composition depth,
- unified builder semantics across report and presentation families,
- final durable continuation model beyond bounded generated-first flows,
- stronger collaboration and good-by-default quality engines as everyday builder behavior.

## 8. Minimal acceptance state now

The first acceptable Wave 2 state is:

- one clearly scoped builder program,
- explicit distinction between artifact family closure and full authoring ambition,
- and one first honest packet that deepens authoring without rewriting the whole stack.

## 9. Full 100% target state

The full builder reaches 100% only when users can:

- generate, edit, restructure, review, and deliver report and presentation artifacts,
- work durably across versions,
- and experience a serious authoring environment rather than one-shot generation plus export.

## 10. Top missing functions and flows

- structural editing and composition
- durable draft continuation
- richer authoring and rebuild workflows
- builder-level review and version semantics
- cross-format authoring coherence

## 11. Proposed bounded delivery packets

1. `Builder ambition boundary`
2. `First rich-authoring packet`
3. `Durable draft continuation depth`
4. `Cross-format builder coherence`

## 12. Risks and dependencies

- depends on `Documents`, `Presentations`, `Outputs Library`, and `ArtifactRun`,
- risks being confused with substrate/library work,
- risks turning Wave 2 into a hidden full editor rewrite without boundaries.
