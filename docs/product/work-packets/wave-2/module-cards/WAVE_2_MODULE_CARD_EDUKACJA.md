# Wave 2 Module Card — Edukacja

> Cluster: `Knowledge And Support Systems`
> Scope: standalone learning and enablement product beyond embedded help

## 1. Module scope

This card covers:

- structured learning,
- enablement programs,
- guided adoption,
- academy-style learning paths,
- and product education as a first-class module.

## 2. Source of truth reviewed

- `docs/product/TRANSFORMATION_ACADEMY_AND_ENABLEMENT_RUNTIME_V8.md`
- `docs/product/HELP_KNOWLEDGE_BASE_V8_MASTER_SUMMARY.md`
- `docs/product/SYSTEMATYKA_PRZEGLADU_V8.md`
- `docs/product/work-packets/cursor-work/V8_V81_CLOSURE_LEDGER.md`

## 3. Intended product behavior

`Edukacja` should be a real enablement system:

- onboard users into product value,
- teach methodology and transformation knowledge,
- provide structured learning journeys,
- and support skill growth over time.

## 4. Current repo and doc truth

Current truth is weak:

- the closure ledger explicitly defers standalone `Edukacja`,
- `SYSTEMATYKA` says there is no real package,
- and the strongest material currently lives as an extension inside Help/KB and academy docs,
- so this is a real Wave 2 module, not a residual polish task.

## 5. Competitive standard

The benchmark is modern enablement and academy systems where:

- learning paths are explicit,
- guided progression exists,
- and learning is tied to real work, not only static content.

## 6. Current-state assessment

- `User value`: low today as a standalone module, high strategic potential.
- `Flow completeness`: low. No standalone module flow is closed.
- `UX quality`: low. The product shell is not defined.
- `Data / logic quality`: partial. Some academy logic exists in surrounding docs.
- `Integration quality`: partial. It attaches naturally to Help/KB and Partner.
- `Trust / governance`: partial. Lifecycle and governance need definition.
- `Market standard fit`: low. This remains mostly a planning gap.

## 7. Main gaps

- no standalone V8 package,
- no canonical shell,
- no structured learning-path model,
- no relationship defined between product help and product education,
- no runtime ownership model.

## 8. Minimal acceptance state now

The first acceptable Wave 2 state is:

- one canonical enablement scope statement,
- one learning-path model,
- and one decision about which education belongs inside Help/KB versus inside a standalone education surface.

## 9. Full 100% target state

`Edukacja` reaches 100% only when it provides:

- structured learning journeys,
- adoption and enablement tracks,
- progress visibility,
- role-aware learning recommendations,
- and clean integration with Help/KB, Partner, and core product onboarding.

## 10. Top missing functions and flows

- academy/learning-path model
- role-based enablement flow
- progress and completion model
- integration with onboarding and help
- content governance for education-specific material

## 11. Proposed bounded delivery packets

1. `Edukacja scope statement`
2. `Learning-path and progress model`
3. `Help/academy boundary definition`
4. `Enablement runtime and governance`

## 12. Risks and dependencies

- depends on `Help / Knowledge Base`, `Partner Program`, and `Landing/onboarding`,
- risks being absorbed and forgotten inside Help,
- risks becoming content-only without a user journey.
