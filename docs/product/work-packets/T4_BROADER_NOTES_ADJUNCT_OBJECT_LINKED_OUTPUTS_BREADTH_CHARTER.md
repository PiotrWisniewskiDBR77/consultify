## 4. First bounded packet

### Packet name

`notebook capture upload authority continuity seam`

### Why this packet starts first

- the active notebook `NewPageModal` upload CTA is still driven by the legacy `/api/notebook/capture/upload` path while notebook core reads/writes and convert continuity already prefer governed V8-first seams
- `Api.uploadNotebookFile()` already resolves the created page back through governed notebook readback, which makes upload initiation authority the smallest real split-brain still visible on the live notebook surface
- this closes one active user-facing capture seam without smuggling broader attachment/output redesign or wider notebook architecture work into the same packet

### Packet scope

- add governed V8-first parity for notebook capture upload initiation
- move the active notebook upload CTA onto a governed V8-first seam
- preserve the existing created-page readback contract on success
- keep wider attachment browsing, output redesign, and broader object-linked outputs breadth outside this packet

## 5. Lane acceptance target

This broader lane is not done after one upload packet.

The lane will be accepted only when:

1. the remaining broader `Notes` adjunct / object-linked outputs residuals are broken into honest bounded packets,
2. those packets land with real runtime and visible surface continuity,
3. no smaller real packet remains,
4. and the lane can be accepted without silently broadening into a whole notebook/output architecture rewrite.
