# Wave 1A Scope Freeze

Date: 2026-03-29
Owner: Cursor agent
Status: proposed execution scope freeze
Purpose: freeze `Wave 1A` as the P0 remediation stage after the full Wave 1 audit

## Definition

`Wave 1A` is the first remediation stage after formal Wave 1 closure.

It exists to close only the `P0` gaps from:

- `docs/product/work-packets/cursor-work/wave1-full-audit/WAVE1_GAP_BACKLOG_2026-03-29.md`
- `docs/product/work-packets/cursor-work/wave1-full-audit/WAVE1_MASTER_AUDIT_2026-03-29.md`

`Wave 1A` is not:

- a reopening of Wave 1 closure
- a full parity program
- a rewrite of integration, calendar, execution, results, or finance architecture

## In scope

Only these four remediation packets:

1. `Integracja provider onboarding and lifecycle parity`
2. `Kalendarz external parity and workload depth`
3. `Wdrożenia write continuity and runtime unification`
4. `KPI + Finanse consequence runtime unification`

## Why these four

These are the only gaps currently classified as `P0` because they still weaken:

- believable end-to-end operator use
- user trust in live connected/runtime systems
- the core operating credibility of the business spine

## Out of scope

The following stay outside `Wave 1A` and move to later stages:

- `Radar` decision-support deepening
- `Notatki` adjunct breadth and provenance
- `Teresa` workspace handoffs and deeper copilot continuity
- `Ankiety` operator workflow depth
- `Wnioski w Interview` actionability depth
- `Inicjatywy` write-family cleanup beyond the direct P0 spine
- `Mind map`, `Whiteboard`, `Proces flow`, `Tabele`
- `Anna` commercial-strengthening layer
- carried modules `Help / Baza wiedzy` and `Program partnerski`

## Non-negotiable scope rule

No `Wave 1A` packet may silently expand into:

- full provider/platform breadth
- full PMO suite parity
- full BI parity
- full finance-platform breadth

If deeper breadth is needed, it must be cut forward into `Wave 1B` or `Wave 1C`.

## Exit condition

`Wave 1A` ends only when:

- each of the 4 `P0` packets has one execution brief
- each brief has a concrete code/test surface map
- each brief has an acceptance proof plan
- the boundary to `Wave 1B` and `Wave 1C` is explicit
