# P27-B Lock — Session → Result → Promotion Closure

- **Status**: `released`
- **Started**: 2026-03-31
- **Released**: 2026-03-31
- **Owner**: cursor-agent

## Delivered scope

1. **Session persistence alignment**: Extended `UpdateToolSessionSchema` with `status`, `wizardState`, `missingItems`, `failureReason`. DB columns: `wizard_state_json`, `missing_items_json`, `failure_reason`, `last_generation_batch_id`. Status transition validation with explicit allowed transitions map.
2. **Finalize gating**: `FINALIZED` status blocked when unresolved `blocker` severity `missingItems` exist. Server returns `409` with `unresolvedBlockers` list.
3. **Idempotent initiative generation**: Dedup guard checks existing batch by `methodology_id + count` before creating new batch. Returns existing initiatives on retry with `deduplicated: true`.
4. **Explicit failure state**: `FAILED` status in transition map. `failureReason` persisted. `POST /:toolId/retry` endpoint resets to `IN_PROGRESS` and clears failure. Generation errors auto-set `FAILED` with reason.
5. **Report/Presentation promotion**: `POST /:toolId/promote` creates downstream artifacts (report/presentation/idea) with traceability links back to session. Requires `APPROVED/GENERATED/FINALIZED` status.
6. **E2E integration tests**: 25 tests covering 2 archetypes (strategic + operational), full lifecycle, failure/retry, promotion, regression.
