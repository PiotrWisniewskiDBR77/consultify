### Staging proof (10-step)
1. Create 10 conversations → POST /api/conversations works; conversations appear in sidebar grouped by time.
2. Rename a few → PATCH with title + titleSource='user' persists; inline rename in ConversationItem works.
3. Pin/star some → PATCH starred=true; pinned group appears at top of ConversationList.
4. Move into folders via DnD → DnD handler calls moveConversationToProject; conversation moves between FolderSection groups.
5. Archive 2 threads → PATCH archived=true; threads move to archived group; distinct from delete (no deleted_at).
6. Unarchive one → PATCH archived=false; thread returns to time-based group.
7. Delete with destructive confirmation → window.confirm with explicit "destructive" message; DELETE endpoint sets deleted_at (soft-delete); conversation disappears from list (excluded by deleted_at IS NULL filter).
8. Server-side search → GET /api/conversations/search?q=... returns results with cursor pagination, filters, message content search; ChatHistorySidebar debounces and shows loading state.
9. Deep-link to archived thread → GET /api/conversations/:id returns _state='archived' + messages; ConversationRouteSync loads it.
10. Team folder permission denial → Backend returns 403 for unauthorized team access; no data leakage; frontend clears active conversation on 403.

### Rollback posture
- Disable destructive delete: remove ?force=true purge endpoint; soft-deleted conversations remain accessible.
- Preserve archive: archive is reversible and independent of delete.
- No data destruction: soft-delete grace window preserves all data until explicit purge.

### Known limits
1. Semantic ranking not implemented (lexical match + recency + pinned boost only).
2. Full-text search uses ILIKE (no dedicated FTS/tsvector index; acceptable for current scale).
3. Grace window purge is manual (no automated cron; org can trigger via force=true).
4. Team folder permission denial shows generic 403 error (no custom denial guidance component).
5. No "delete my data" self-service UI (backend supports it; UI is out of P35 scope).
6. No cross-tenant/cross-org enumeration (by design — findAccessibleConversation enforces ownership + team membership).
