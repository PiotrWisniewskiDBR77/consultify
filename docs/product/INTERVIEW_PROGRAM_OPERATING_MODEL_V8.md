# Interview Program Operating Model v8

> Status: Draft v8
> Owner: Product + Engineering
> Scope: canonical program, wave, coverage and research-operations model for Interview without changing the core session mechanics

---

## 1. Why this document exists

The Interview module should support not only one-off sessions but organized programs of inquiry.

This document defines how Interview works as a managed operating model around sessions.

---

## 2. Core statement

`Interview` should support:

- single interview sessions
- multi-participant waves
- program-level coverage tracking
- governed synthesis across many sessions
- consulting-style discovery built around explicit goals and hypotheses

without replacing the core interview mechanics already present.

---

## 3. Canonical program objects

The operating model should include:

- `InterviewProgram`
- `InterviewWave`
- `InterviewCoveragePlan`
- `InterviewDiscoveryBrief`
- `InterviewHypothesis`
- `InterviewSession`
- `InterviewParticipantRef`
- `InterviewInsightBatch`

---

## 4. Program-level rules

The platform should support:

- target participant groups
- weighted stakeholder coverage
- topic coverage goals
- open coverage gaps
- hypothesis status tracking
- session status by wave
- review and synthesis checkpoints

---

## 5. Coverage doctrine

Coverage should not be measured only by number of responses.

It should also consider:

- respondent role
- influence weight
- risk of omission
- org area
- initiative relevance
- unanswered critical themes
- evidence sufficiency

---

## 6. Program outcomes

Interview programs should feed:

- insight rollups
- gap identification
- change-management input
- organizational knowledge capture
- decision-ready consulting synthesis
