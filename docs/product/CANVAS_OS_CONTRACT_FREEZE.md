# Canvas OS Contract Freeze

## Purpose
This document freezes the runtime contract for `Canvas OS` inside `Idea Workspace`.
It is the canonical acceptance layer for `Mind Map`, `Whiteboard`, `Process Flow`, and `Table` without changing frozen workspace IA.

## Non-Negotiables
- `One idea = one workspace` stays unchanged.
- `Mind Map`, `Whiteboard`, `Process Flow`, and `Table` remain the only four local work systems.
- The right strip remains exactly `Tools | Context | AI Suggestions`.
- The left discovery rail is allowed only as a discovery/library layer and must not replace the workspace shell.
- `Process Flow` remains one engine with formal semantic kits; `VSM` is never reduced to a generic flowchart skin.
- AI must keep the contract `proposal -> preview -> accept/reject`.
- Manual editing remains first-class across all surfaces.

## Canvas OS Promise
`Canvas OS` is not a generic infinite canvas wrapper.
It must win through:
- shared graph across the four work systems,
- diagram-native traceability,
- governed AI with auditability,
- formal semantic kits where required,
- diagram-to-execution promotion without losing source context.

## Capability Labels
Use these labels consistently in docs, UI, QA, and code review:
- `real`: workflow is complete end-to-end for the promised user path.
- `partial`: workflow is usable but one material step is still weak, indirect, or missing.
- `scaffold`: UI or runtime seam exists, but the workflow should not be treated as complete.
- `missing`: planned capability is not yet implemented in the product.
- `out_of_scope`: explicitly not part of the current rollout cutline.

## Parity Targets
- shared viewport grammar
- discovery-first canvas start
- searchable template/library entry
- formal process/diagram semantics
- export baseline
- collaboration visibility

## Differentiator Targets
- diagram object refs on shared graph
- `Used in` and backlinks from canvas artifacts
- governed AI proposal review
- `Process Flow -> ROI -> Initiative` promotion paths
- traceable conversion into execution artifacts

## Runtime Boundaries
### Shared shell
- workspace orchestration
- left discovery rail
- right strip panel switching
- shared selection and insert events
- export/share entry points
- AI proposal review overlay

### Local canvas runtime
- tool-specific editing interactions
- validators
- semantic kits and node libraries
- local render-specific overlays

### Shared governance layer
- capability labels
- audit/replay payloads
- review state
- share policy
- template metadata

## Exit Rule
The rollout is complete only when runtime behavior matches this document.
Labels, buttons, or shell affordances alone do not count as completion.
