> Status: Draft v8
> Owner: Product + Engineering
> Purpose: be the canonical entrypoint for the whole `Idea` module, unifying the shared workspace doctrine, all four native work systems, and the final integration layer with the rest of Consultify

---

## 1. Why this document exists

`Idea` is no longer just one canvas or one experimental workspace.

It is now one of the most strategically important modules in the product because it is where:

- loose thinking becomes structured work
- structured work becomes decision support
- decision support becomes execution-ready artifacts

The documentation package was created step by step:

1. shared workspace/navigation doctrine
2. `Mind Map`
3. `Whiteboard`
4. `Process Flow`
5. `Table`
6. integration with the rest of Consultify

This document exists to close the loop and answer one question:

`Is the whole Idea module now documented strongly enough to treat it as a complete product package rather than a set of separate canvas documents?`

---

## 2. Executive verdict

Current verdict for `Idea` is:

`The Idea module now has strong v8 documentation coverage across workspace organization, all four native work systems, and the integration/promotion layer. The remaining blockers are primarily implementation, runtime hardening, and package cleanup, not missing core product doctrine.`

This means:

- the module is no longer under-specified
- the module is no longer mainly blocked by conceptual gaps
- the largest remaining risk is now implementation quality, consistency, and traceable integration into the wider system

## 4. What the Idea module now is

The final product understanding should be:

`Idea` is one AI-native problem-solving environment where one idea becomes one workspace, four native work systems cooperate on the same identity, and the outputs can be promoted into real platform artifacts without losing traceability.

The four native work systems remain:

1. `Mind Map`
2. `Whiteboard`
3. `Process Flow`
4. `Table`

The module is not:

- a launcher for detached mini-products
- a whiteboard with a few side tools
- a mind map with optional extras
- a table system pretending to be the whole idea module

## 8. Real remaining blockers

The real remaining blockers are now mostly implementation-facing:

1. runtime consistency across all four systems
2. shared shell and shared primitive hardening
3. promotion flows and integration adapters that behave consistently
4. cross-canvas persistence and traceability hardening
5. cleanup of legacy or misleading documents/code paths that can create false confidence
6. packaging and repository hygiene so the final canonical path is obvious

These are serious blockers, but they are no longer mainly conceptual blockers.

---

## 9. Biggest product truth

The biggest truth about `Idea` is:

`The module is only valuable if it behaves like one thinking-to-execution system, not four strong canvases placed next to each other.`

That means:

- excellence of each canvas matters
- but the integration layer matters just as much

Without that integration layer:

- work stays interesting but trapped
- promotion stays manual
- AI context stays local
- downstream execution loses idea truth

With that integration layer:

- `Idea` becomes the canonical transformation workspace for the whole product
