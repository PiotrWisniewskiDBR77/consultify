## 🔴 GŁÓWNE ODKRYCIE — generator F1 nie miał szablonów (24/25 sekcji)
**Objaw:** R2/R3, które zbudowałem, byłyby w praktyce bezużyteczne — bo brain
(`generateFullInitiative`) nie miał z czego generować.

**Przyczyna źródłowa:** kolumna `initiative_section_types.key` trzyma **camelCase**
(`problemDefinition`), a lookup to `WHERE key = ?` (camelCase). Ale migracja
`530_initiative_section_ai_prompts.sql` ustawiała `ai_prompt_template`
`WHERE key = 'problem_definition'` (**snake_case**) → UPDATE-y trafiały w **0 wierszy**.
Migracja `542` poprawiła 4 sekcje, ale została zaaplikowana ZANIM wiersze
pasowały (status `success`, 0 rows). Efekt: **24 z 25 sekcji miało pusty szablon**
→ `generateSectionContent` rzucał „AI prompt template is not configured" dla każdej
karty rdzenia → brain fail-soft pomijał wszystko → zero treści → R3 nic nie hydratuje.

**Fix:** nowa migracja `20260628_initiative_core_section_prompts.sql` — ustawia
szablony dla **wszystkich 6 kart rdzenia** (CORE_SECTION_KEYS: problemDefinition,
targetState, kpis, scope, control, financialImpact) pod camelCase, idempotentnie.
Kształty JSON **zgodne z parserem FE i hydracją R3** (scope → inScope/outOfScope/
killCriteria → scope_in/scope_out/kill_criteria; problemDefinition → symptom →
problem_statement; targetState → successCriteria/deliverables). Commit `53d19cb9a6`.

**Zweryfikowane (staging/trolley):** wszystkie 6 kart rdzenia mają teraz szablon
emitujący JSON (raw query: len 438–533, `Return valid JSON`=true). Lookup
`WHERE key=$1 AND is_active=1` zwraca szablon. ✅

uruchamia tylko migracje Table Platform (7xxx), NIE ogólne. Więc trzeba odpalić
