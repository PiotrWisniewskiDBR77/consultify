# EXTRA (poza kodem) — treści i osobne inicjatywy

Te tematy **nie powinny blokować** paczek engineering. Robimy je równolegle “na boku” lub w osobnym sprint-cadence.

## EXTRA 1 — Materiały edukacyjne (treści) — T074–T085
Uwaga: “moduł edukacji” może wymagać drobnego plumbing w kodzie, ale **tworzenie treści** robimy oddzielnie.

**Podzadania (content pipeline):**
1. **Syllabus + IA**:
   - lista kursów: fundamentals / change mgmt / prompt engineering / tools / licensed tools / initiatives / finance / ROI / KPI / presentations / report templates
2. **Core lessons (EN+PL manual)**:
   - 8–12 lekcji “must-have” (krótkie, konkretne, platform-first)
3. **Machine translation pack (DE/ES/AR/JA)**:
   - auto-translate + review krytycznych ekranów (szczególnie RTL dla ar)
4. **Ćwiczenia / checklisty**:
   - 1–2 ćwiczenia na kurs
5. **Assets**:
   - grafiki, mini‑diagramy, micro‑videos list (jeśli jest)
6. **Quality gate**:
   - zero placeholderów, spójne słownictwo z product narrative.

## EXTRA 2 — Demo company website (case page) — T088
To jest głównie **strona i treści** (marketing/case study), nie core backend.

**Podzadania:**
1. IA strony (sekcje, CTA, deep links do app)
2. Copy EN+PL (manual)
3. Pozostałe języki (DE/ES/AR/JA) — machine + quick QA
4. Screenshoty / grafiki (spójne z “Tech Sexy”)
5. SEO/meta + performance budżet (obrazy)

## EXTRA 3 — Mobile app do Lean data collection — T029
To jest osobny “produkt” (field capture). Jeśli robimy to w V2, to najlepiej jako odseparowany tor.

**Podzadania (gdy włączymy):**
1. UX “floor capture”: szybkie formularze, checklists, notatki, zdjęcia (jeśli), minimal steps
2. Offline-first queue + sync policy (retry, konflikty)
3. Kontrakty API (ingestion endpointy, auth, rate limit)
4. QA w terenie (low network) + bezpieczeństwo (brak PII w logach)
5. Release plan (pilot na 1–2 klientach)

To jest głównie content + wizualny refresh; engineering tylko “route integrity” i techniczne elementy (i18n, links).
