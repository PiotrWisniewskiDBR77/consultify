# Sales Outreach Playbook — Clients

Operacyjny playbook outreachowy dla sprzedaży do klientów końcowych Consultify.

- [`../assets/client/`](../assets/client/) — materiałów do wysyłki.

---

## 1. Główna zasada

Zawsze zaczynaj od **problemu biznesowego**, a nie od narzędzia.

Schemat:
1. wejście przez najbardziej prawdopodobnego sponsora,
2. przejście na odpowiedni proof,
3. włączenie CFO i IT,
4. domknięcie przez pilot, governance i security.

---

## 2. Kogo atakować pierwszego

### Standardowy porządek

1. **Owner / CEO** — jeśli konto jest na etapie strategicznego impulsu.
2. **CFO** — jeśli temat jest blokowany przez ekonomię.
3. **COO / Transformation Officer** — jeśli konto czuje chaos delivery i brak ownership.
4. **IT / Cybersecurity** — gdy wchodzimy w architekturę, dane i warunki wdrożenia.

### Reguła

Nie próbuj zamknąć enterprise wyłącznie przez jedną personę.  
Consultify wygrywa wtedy, gdy buduje **jedną narrację dla komitetu**.

## 3. Matrix outreach per persona

| Persona | Entry point | Trigger | First proof | Desired next step |
|---|---|---|---|---|
| Owner | wartość firmy, przewaga, chaos AI | presja strategiczna, wzrost, exit, nowy program | category one-pager | 30-min strategic call |
| CEO | wynik, pozycja lidera, tempo | presja kwartalna, wiele inicjatyw bez widoczności | executive memo / case | demo + call z CFO/COO |
| CFO | ROI, governance, persistence | blokada budżetu, rozjazd ROI vs wynik | ROI template | workshop ROI + conditions list |
| COO | chaos delivery, bottlenecks | eskalacje, opóźnienia, konflikt priorytetów | pilot / rollout plan | operational workshop |
| Transformation Officer | rozproszone portfolio | brak jednego obrazu programu | governance narrative | PMO / steering session |
| IT / Cybersecurity | black box, dane, ryzyko | vendor review, polityka danych, audit pressure | security brief | technical review |

## 5. Typowe ścieżki wejścia

### Outbound cold

Najlepszy dla:
- Owner,
- CEO,
- CFO,
- partner referrals.

Rola pierwszej wiadomości:
- nie domknąć,
- tylko ustawić właściwy problem i uzyskać mały next step.

### ABM / multi-thread

Najlepszy dla:
- enterprise,
- złożonego komitetu,
- kont z presją na ROI i compliance.

### Warm intro

Najlepszy dla:
- owner / founder-led motions,
- partner-led intros,
- kont z relacyjnym wejściem.

### Partner-led intro

Najlepszy dla:
- software house,
- SI,
- consulting owner,
- portfel klienta banku / instytucji.

## 6. Sequencing rules

### Rule 1

Jeśli zaczynasz od Ownera lub CEO, CFO i IT muszą wejść **przed** decyzją o pilocie.

### Rule 2

Jeśli zaczynasz od CFO, musisz szybko dołożyć:
- execution ownera (COO / TO),
- security ownera (IT).

### Rule 3

Jeśli zaczynasz od IT, nie próbuj sprzedawać strategii. Najpierw zamknij warunki bezpieczeństwa, potem połącz to z ROI i execution.

### Rule 4

Dla enterprise celem nie jest seria niezależnych rozmów. Celem jest **jedna, wspólna decyzja komitetu**.

## 8. Czego nie robić

- Nie zaczynaj od demka bez ustawienia problemu.
- Nie używaj tego samego komunikatu dla CEO i CFO.
- Nie wysyłaj security briefu jako pierwszego materiału do Ownera.
- Nie obiecuj pilota bez ustalenia success metrics.
- Nie wysyłaj case'a z przykładowymi liczbami jako "realnego" bez zgody i review.
