# AGT-001-T01 — rozmowny intake Teresy do jednego Transformation Case

Status: `READY_SERIAL_INTEGRATOR / PREFLIGHT_REQUIRED`

Baseline przygotowania: `756d904c4`

Gap: `AGT-001-G01`

Owner danych: Agent / `transformation_planning_intakes` i `transformation_cases`

## Objective

Podłączyć istniejący backend Planning Intake do normalnej rozmowy z Teresą.
Jawna prośba o plan transformacji rozpoczyna tenant-scoped intake, Teresa pyta
wyłącznie o brakujące pola, a kompletny intake konwertuje się idempotentnie do
jednego `transformation_cases`. Link otwiera ten sam Case w kanonicznym widoku
Agent. Odświeżenie rozmowy nie gubi niedokończonego intake.

## Evidence i AS-IS

- Detector już istnieje: `transformationIntentDetector.ts` wraz z testem.
- Klient ma start/answer/convert w `services/api/v8/transformation-cases.ts`.
- Route ma POST/PATCH/convert w `transformation-cases.routes.ts`.
- Service i tabela są trwałe oraz mają `conversation_id`, actor, tenant,
  idempotency key i converted case ID.
- Brakuje endpointu odczytującego aktywny intake rozmowy, więc sam stan React
  nie przeżyje cold reload.
- Kanoniczny `UnifiedChatPanel.tsx` nie importuje detectora/API i nie ma intake
  branch przed ogólnym streamingiem.
- Recovery commit `fec04bc5e` zawiera szkic UI flow oraz komunikaty; jest
  niekanonicznym źródłem diffu, nie branch-em do merge.
- `UnifiedChatPanel.helpers.test.ts` zawiera trzy czerwone asercje opisujące
  brakujące helpery; test Deck context należy do osobnego `CHAT-004-G01`.

## Nowy read contract

`GET /api/v8/transformation-cases/planning-intakes/active?conversationId=<id>`
zwraca najnowszy intake `needs_clarification|ready` tylko dla organization i
actor z auth context. Brak zwraca 200 `{ intake: null }`; foreign conversation
nie ujawnia istnienia rekordu. Kolejność route musi poprzedzać `/:intakeId`.

## Required cases

- PL i EN positive intent; podobne, ale niejawne zdanie nie uruchamia intake;
- start replay z tym samym key oraz collision z innym payloadem/aktorem;
- missing outcome/sponsor/scope/horizon, częściowe odpowiedzi i unknown field;
- active-intake recovery po cold reload;
- simultaneous convert/retry daje jeden case ID;
- converted intake nie przechwytuje normalnego chatu;
- tenant/actor/conversation denial;
- zakodowany case ID w linku i normalne otwarcie Agent;
- message persistence degraded oraz API error mają jawny stan bez silent fallback.
