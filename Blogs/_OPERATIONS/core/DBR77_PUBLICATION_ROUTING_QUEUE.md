## Purpose

This file operationalizes:

- `Blogs/_SYSTEM/standards/DBR77_PUBLICATION_OPERATING_CHECKLIST.md`
- `Blogs/_OPERATIONS/core/DBR77_PUBLICATION_MATRIX.md`
- `Blogs/_OPERATIONS/core/DBR77_90_DAY_PUBLICATION_FRAMEWORK.md`

Use it as the live routing layer from package to LP to CTA to publish.

## Mandatory Workflow

Every asset moves through the same sequence:

1. package ready in `EN`, `PL`, `DE`
2. LP section assigned
3. persona and funnel stage locked
4. face and region assigned
5. CTA approved
6. website article published
7. personal post published
8. company amplification published
9. email or outbound derivative handed off

Do not skip LP placement and CTA assignment.

## CTA Routing Rule

| Funnel stage | Allowed CTA family | Do not use |
|---|---|---|
| first contact | read, explore, benchmark | hard decision CTA |
| consideration | compare, scope, plan pilot, book workshop | adoption CTA |
| decision | start demo, review business case, review security, schedule decision meeting | vague awareness CTA |
| adoption | activate next use case, expand, measure impact | first-contact CTA |
| nurture | stay close, join webinar, follow topic | pressure CTA |

## Package-To-Publish Backlog

Every product package is only complete when all four states are true:

- `package ready`
- `LP placed`
- `CTA wired`
- `publish queued`

If a package is missing one state, it is not release-ready.
