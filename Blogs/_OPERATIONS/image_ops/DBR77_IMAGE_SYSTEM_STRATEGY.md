# DBR77 Image System Strategy

## Purpose

This file defines the professional visual standard for the full DBR77 image system.

Use it as the source of truth for:

- image strategy
- prompt rewrites
- quality review
- generator assignment
- blog, website, social, and newsletter image production

## North Star

Every image should feel like it came from a serious industrial publisher, not from an AI image demo.

The buyer should feel:

- these people have seen the real operating environment
- these people understand where decisions fail
- these people know how work moves from signal to action
- these people are credible enough to advise both leadership and the floor

An image is not decoration.

An image must do at least one of these jobs:

1. increase trust through operational credibility
2. explain the article argument more clearly
3. make the content more reusable in social or newsletter channels

## Core Image Rule

Graphics should prove the article thesis, not merely signal the topic.

A weak image says:

- AI
- technology
- factory
- innovation

A strong image says:

- this exact operating problem
- this exact handoff, risk, approval, or control point
- this exact decision structure
- this exact before-versus-after business shift

## The New Professional Reset

From this production window forward, DBR77 should no longer optimize for "acceptable AI images."

It should optimize for:

- first-glance human believability
- editorial seriousness
- physical plausibility
- restrained visual intelligence
- thesis clarity without software-dashboard aesthetics

If an image looks like a typical generative image at first glance, it is not good enough for the new standard even if it is technically usable.

## What Makes An Image Look "AI"

The system must actively block these cues:

- over-clean conceptual still lifes with no real-world friction
- glowing boards, neon rails, or polished sci-fi control surfaces
- impossible mixed scenes that combine too many ideas at once
- fake UI, fake dashboards, fake charts, or pseudo-infographic panels
- readable or nearly readable text artefacts
- overly symmetrical compositions with no believable camera choice
- hyper-smooth materials, plastic-looking surfaces, or sterile workshop setups
- "smart-looking" props that look designed for the prompt instead of the workflow

## The New Visual Languages

DBR77 should now work with three role-specific visual languages rather than one generic industrial-AI look.

### 1. Editorial Industrial Photography

Use primarily for `Hero`.

Characteristics:

- looks like a real commissioned editorial shoot
- believable lens, distance, and depth of field
- real surfaces, wear, clutter, and material variation
- people behave naturally inside a workflow moment
- one clear business meaning anchored in a physical scene

### 2. Tight Editorial Crop

Use primarily for `Social`.

Characteristics:

- one dominant object, gesture, lane, or control moment
- strong thumbnail read
- simpler than `Hero`
- closer framing
- avoids setup-looking concept compositions

### 3. Physical Explanatory Construction

Use primarily for `Analytical`.

Characteristics:

- explains one idea using physical logic rather than software logic
- uses trays, rails, gates, tokens, ledgers, packets, clips, boards, fixtures, markers, checkpoints, or mechanical routing
- feels like a photographed or fabricated explanatory installation
- avoids panel UI, fake charts, and slide aesthetics

## Three Required Roles

Every publishable article package should define three image roles.

### Hero

Purpose:

- establish trust
- show the real operating or decision environment
- signal that DBR77 understands the field

Default usage:

- top of article page
- LP entry blocks
- feature tiles

Default aspect ratio:

- `16:9`

Hero should feel like:

- a still from a serious industrial editorial story
- a photographed decision moment
- a real work environment with one business thesis embedded in it

Hero should not feel like:

- a concept board
- a tabletop metaphor with too many props
- a command center, dashboard wall, or AI demo

### Analytical

Purpose:

- explain the main framework, comparison, sequence, or decision structure
- make the article more quotable, referenceable, and reusable

Default usage:

- mid-article placement
- inline proof block
- presentation or sales reuse

Default aspect ratio:

- `16:9`
- `3:2` only when the explanatory layout truly needs it

Analytical should feel like:

- a physical explanatory object or photographed decision model
- a premium editorial explainer
- one idea made visible in under three seconds

Analytical should not feel like:

- a PowerPoint slide
- a dashboard screenshot
- a UI mockup
- a chart board with fake labels

### Social

Purpose:

- stop scroll
- carry one clear thesis
- support reuse in LinkedIn, email, and share cards

Default usage:

- company page
- expert profile post
- newsletter module
- social preview image

Default aspect ratio:

- `1:1`
- optional `4:5` variant for LinkedIn

Social should feel like:

- a strong editorial crop
- a single memorable business metaphor
- a quick-read image that survives thumbnail size

Social should not feel like:

- a miniature poster
- a document scan
- a dense explainer squeezed into a square

## Scene Construction Rules

Every future prompt should obey these rules:

1. One image = one visual claim.
2. One role = one main subject hierarchy.
3. One scene = one believable camera position.
4. Prefer a physical workflow moment over a symbolic concept arrangement.
5. Prefer real materials and believable wear over sleek "innovation" polish.
6. Use fewer elements, but make them more specific.

## Camera Reality Rules

Prompts should now anchor:

- camera distance
- framing logic
- lens feel
- light quality
- material realism
- surface wear
- depth of field
- imperfection cues

Good anchors:

- waist-high view across a real coordination table
- close crop on one approval gate with shallow depth of field
- overhead editorial shot of a physical routing board with worn metal rails
- side-lit industrial floor with mixed practical light and natural falloff

Weak anchors:

- premium industrial editorial realism
- futuristic but grounded
- strategic infographic style
- beautiful factory scene

## Credibility Guardrails

Always avoid:

- generic blue dashboards
- sci-fi holograms
- cyberpunk palettes
- glowing robot faces
- random server racks without context
- empty showroom factories
- handshake stock scenes
- smiling office poses with no operating logic
- abstract AI brains
- fake software panels
- readable or nearly readable microcopy
- giant punctuation marks
- posterized symbolic AI metaphors

Prefer:

- plant-floor context
- ownership and approval moments
- trade-off scenes
- incident-to-response loops
- control boundaries
- handoff points
- packets, ledgers, trays, rails, and gates
- restrained documentary messiness

## Writing Rules

### Objective

Describe the job of the image, not the topic.

Good:

- show that bounded rollout beats uncontrolled expansion
- show that approval delay creates operational friction

Weak:

- create a strong image about factory AI

### Claim To Prove

This replaces the older, looser thesis wording.

State the article argument that the image must make believable.

Examples:

- visibility without response logic still creates waste
- decision automation only works under visible thresholds
- operational data helps only when it reaches live execution

### Single Scene

Describe one scene only.

Do not pile multiple ideas into one shot.

### Camera Framing

State how the image is seen:

- overhead editorial shot
- waist-high documentary view
- tight close crop
- shallow-depth closeup

### Lens / Distance

State the visual distance:

- close editorial crop
- medium documentary distance
- overhead wide table read

### Material Cues

Ask for believable physicality:

- worn metal
- paper edges
- grease marks
- scuffed paint
- mixed plastics and steel
- real workshop wood

### Imperfection Cues

Ask for controlled realism:

- slight disorder
- natural wear
- non-symmetric placement
- believable tool scatter
- practical light variation

### Constraints

Use constraints to reduce drift.

Default constraints for the new system:

- no readable text
- no logos
- no brand names
- no fake dashboards
- no sci-fi UI
- no staged stock poses
- no over-clean symmetry

### Negative Prompts

Negative prompts should now block failure modes explicitly:

- dashboard screenshot
- control-room UI
- slide infographic
- fake chart labels
- glowing hologram
- AI concept art
- generative sterility
- toy-like model board

## Channel Reuse Rules

### Website

- `Hero` should support trust and article entry
- `Analytical` should increase comprehension without looking like a slide
- alt text must describe the business meaning, not only the literal scene

### Social

- `Social` should carry one thesis only
- do not rely on model-generated typography
- keep the focal subject safe for cropping and overlays

### Newsletter

- default to `Social` when one thesis dominates
- use `Hero` when the module needs more trust and less visual aggression
- use `Analytical` only when the audience is already warm and the image still reads quickly

## Image Review Gate

An image is ready only when all of these are true:

1. It expresses the article claim, not only the topic.
2. It feels believable at first glance.
3. It avoids stock, sci-fi, dashboard, and generic AI cliches.
4. It looks professionally publishable without excuses.
5. It can be reused in at least one distribution channel.

If any answer is no, the prompt needs revision before more generation continues.
