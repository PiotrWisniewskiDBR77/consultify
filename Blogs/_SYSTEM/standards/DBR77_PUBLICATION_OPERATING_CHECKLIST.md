# DBR77 Publication Operating Checklist

## Purpose

This checklist turns the DBR77 publication strategy into a repeatable operating workflow.

Use it before any major asset is drafted, approved, published, or repurposed.

It is designed to answer five practical questions:

1. who is this asset for
2. which product gate should own the entry
3. which face should publish or amplify it
4. which funnel stage and CTA should it support
5. what derivative set should be produced from the core asset

## Source Order

Use these documents in this order:

1. `Blogs/_SYSTEM/strategy/DBR77_PRODUCT_MARKETING_PLAN.md`
2. `Blogs/_OPERATIONS/core/DBR77_PUBLICATION_MATRIX.md`
3. `Blogs/_OPERATIONS/core/DBR77_FUNNEL_ASSET_MAP.md`
4. `Blogs/_OPERATIONS/core/DBR77_90_DAY_PUBLICATION_FRAMEWORK.md`

If there is a conflict, the product marketing plan wins.

## Operating Rule

Do not start from format.

Start from:

1. entry product
2. persona
3. funnel stage
4. face
5. CTA

Only then choose article, post, email, or company amplification.

## Step 1: Set The Entry Gate

Every asset must have one primary entry product.

Use this rule first:

- `DBR77` content = system, trust, cross-product logic, category explanation
- product content = problem, decision logic, outcome, and next step

Default gate logic:

- `Consultify` = transformation, governance, ROI, portfolio control
- `IoT` = visibility, downtime, machine data, retrofit starts
- `IRIS` = execution layer, tasking, approvals, plant operating system
- `DT` = simulation, scenario testing, CAPEX confidence, flow decisions
- `Marketplace` = sourcing clarity, offer comparison, buying governance
- `Vector` = secure industrial AI, deployment trust, data sovereignty, approval

Checklist:

- [ ] primary product gate is named
- [ ] optional secondary bridge is named only if it strengthens the main story
- [ ] asset does not start from "the DBR77 system" when a product gate should lead

## Step 2: Lock Persona

Every asset must serve one primary persona.

Default persona routing:

- `Owner / President / Chairman` = strategic confidence, system logic, ROI, board clarity
- `Plant Manager / Operations` = operating reality, implementation, downtime, flow, adoption
- `CFO` = CAPEX confidence, business case, risk, payback, scenario comparison
- `CTO` = architecture, integration, governance, secure AI, control boundaries
- `Purchasing / Supplier / Integrator` = comparability, sourcing workflow, supplier evaluation

Checklist:

- [ ] one primary persona is named
- [ ] the problem statement reads like that persona would say it
- [ ] proof logic fits the persona's decision style
- [ ] CTA fits the persona's next realistic action

## Step 4: Choose Funnel Stage And CTA

Every asset must support one funnel stage.

### First Contact

Use when the goal is credibility, relevance, and curiosity.

Best CTAs:

- read
- benchmark
- explore
- see how others approach this

### Demo / Trial Entry

Use when the goal is to reduce uncertainty and show realistic upside.

Best CTAs:

- start demo
- start trial
- plan a pilot
- book workshop

### Buying Decision

Use when the goal is to de-risk the purchase and help internal justification.

Best CTAs:

- validate fit
- review business case
- review security
- schedule decision meeting

### Product Use / Adoption

Use when the goal is faster time-to-value and wider product use.

Best CTAs:

- activate next use case
- expand module
- measure impact
- explore advanced workflow

### Nurture For Non-Buyers

Use when the goal is trust without pressure.

Best CTAs:

- stay connected
- keep following this topic
- watch this space
- learn how others are solving this

### External Visibility

Use when the goal is awareness, authority, and category visibility.

Best CTAs:

- watch
- attend
- subscribe
- connect

Checklist:

- [ ] one funnel stage is named
- [ ] CTA style matches the stage
- [ ] CTA is realistic for the persona and product maturity
- [ ] asset does not use a decision CTA when it is only a first-contact asset

## Step 5: Set The Content Layer And Proof Type

Every asset should be tagged internally by:

- content layer
- proof type

Use these content layers:

- field reality
- problem deep dive
- solution logic
- decision support
- execution and transformation

Use these proof signals:

- case-shaped thinking
- operational specificity
- repeatable insight pattern
- process clarity
- outcome logic
- visible depth

Checklist:

- [ ] content layer is named internally
- [ ] proof type is named internally
- [ ] article includes operational vocabulary, not generic business language
- [ ] article sounds like repeated industrial practice, not content sprint output

## Step 6: Build The Core Asset First

One strong core asset should drive the rest.

Minimum derivative set:

- website article
- personal post
- company post
- email angle
- sales snippet
- `2-3` image prompts

Use this sequence:

1. write the durable website article
2. extract the personal point of view for the right face
3. create the company amplification angle
4. write the email angle for the primary persona
5. write the sales snippet for direct use

Checklist:

- [ ] article is the master asset
- [ ] derivatives preserve the same logic, not a new argument
- [ ] derivatives adapt face, region, persona, and CTA correctly
- [ ] company amplification adds synthesis or proof, not a copy of the personal post

- `seo.md`

- `publish.md`
- `social.md`
- `sources.md`

Every major asset must also have:

- persona
- funnel stage
- product bridge
- proof type
- CTA

Checklist:

- [ ] English is the master version
- [ ] localizations preserve meaning
- [ ] `publish.md` reflects the actual page order
- [ ] `social.md` reflects the chosen face and stage
- [ ] no legacy production-note markers remain in article body
- [ ] proof claims are not inflated
- [ ] article still reads like mature industrial practice

Internally, every asset should be tracked by:

- product
- persona
- funnel stage
- region
- face / author
- CTA
- content layer
- proof type
- status

Minimum release record:

- [ ] product
- [ ] asset slug
- [ ] face
- [ ] persona
- [ ] funnel stage
- [ ] CTA
- [ ] derivative set complete or incomplete
- [ ] publication owner
- [ ] publication date or queue status

## Fast Decision Tree

Use this short sequence if the team is moving quickly:

1. What problem is the asset solving?
2. Which product gate should own first contact?
3. Which persona is the primary reader?
4. Which face has the most trust for that reader?
5. Which funnel stage is this really serving?
6. Which CTA is natural at that stage?
7. What proof type makes this believable?
8. Which derivative set will be created from the core asset?

If any answer is missing, the asset is not ready for production.

## Do Not Publish If

- the asset has no clear entry product
- the persona is vague or mixed
- the CTA jumps ahead of the buyer stage
- the face is wrong for the topic or region
- the content sounds like generic B2B thought leadership
- there is no visible proof logic
- the derivative set was not planned

## Output Standard

The publication system is working when:

- each persona sees the right expert and the right product gate
- funnel stages feel intentional, not random
- CTA paths match buyer readiness
- company and personal channels amplify each other without duplication
- website assets remain durable and reusable
- DBR77 looks like accumulated industrial practice, not a content sprint
